# ShopBench — React State Management Comparison

A shopping cart application built **three times** using different state management approaches to benchmark performance, bundle size, and developer experience.

## Implementations

| Version | Library | Directory |
|---------|---------|-----------|
| 1 | React Context API (naive + optimized) | `context-version/` |
| 2 | Zustand | `zustand-version/` |
| 3 | Redux Toolkit | `redux-version/` |

## Running Each Version

### Prerequisites
- Node.js 18+ and npm 9+
- (Optional) Docker and Docker Compose for containerized run

### Context API Version

```bash
cd context-version
npm install
npm run dev
```

- Default URL: http://localhost:5173 → **Optimized** (split contexts)
- Naive version: http://localhost:5173?mode=naive

### Zustand Version

```bash
cd zustand-version
npm install
npm run dev
```

URL: http://localhost:5173

### Redux Toolkit Version

```bash
cd redux-version
npm install
npm run dev
```

URL: http://localhost:5173

## Running with Docker (Redux version)

```bash
docker-compose up --build -d
```

The app will be available at http://localhost:8080

Check health status:
```bash
docker-compose ps
```

Stop:
```bash
docker-compose down
```

## Benchmarking Protocol

### Re-render Profiling

1. Install [React Developer Tools](https://react.dev/learn/react-developer-tools) browser extension.
2. Run the app in dev mode.
3. Open DevTools → **Profiler** tab → check **"Record why each component rendered"**.
4. Click ▶ Start profiling.
5. Click **"Add to Cart"** on the first product **10 times**.
6. Click ⏹ Stop profiling.
7. Analyze the flame graph — hover components to see render counts and reasons.

### Render Counters

Each key component displays a yellow render counter badge (dev mode only):
- `Header` — should NOT re-render on cart changes in optimized/Zustand/RTK versions
- `ProductList` — should NOT re-render on cart changes
- `ProductCard` — should NOT re-render on cart changes (only on its own local state)
- `CartSidebar` — SHOULD re-render when cart changes
- `CartItem` — SHOULD re-render when its item changes

### Bundle Analysis

```bash
npm run build   # generates stats.html
```

Open `stats.html` in a browser to see the interactive treemap.

## Key Findings Summary

| Metric | Context (naive) | Context (split) | Zustand | Redux Toolkit |
|--------|----------------|-----------------|---------|---------------|
| Unnecessary re-renders | High | Low | Low | Low |
| Bundle overhead | 0 KB | 0 KB | ~3 KB | ~16 KB |
| Boilerplate | Minimal | Moderate | Minimal | Moderate |
| Time-travel debugging | ❌ | ❌ | ❌ | ✅ |
| Best for | Prototypes | Small apps | Medium apps | Large teams |
